# Retrospective

## 1. What went well
   One of the biggest postives we found about the project was using rails. Rails
   was incredibly helpful and wee feel it is one the easiest to learn frameworks of what we used it for.
   Especially how quickly it allowed us to create and define our modules. We also felt that the routes it\
   handles automatically were incredibly helpful for saving us time we didn't take to create them ourselves.

   We felt that the UI design was a success. It was designed by us in a way to make the users life
   easier by including menus and not having the user type out every command or expense they wished to view.

   We felt that we handled version control extremely well and never had any issues with conflicting branches, 
   or huge bugs appearing in main.
   
## 2. What was difficult
   The most difficult part of the project was commmunicating with a partner when we could not meet in person
   and all communcation was through slack or zoom.

   It was difficult to implement the realtionship expenses and the implementation that came with thos relationships
   with other models. For example the automatic creation of a category if a new category name is entered by the user when creating an      expense.
   
## 3. What the pair would improve next time
   The communication, such as having more frequent meetings and updating eachother on slack more often.

   The UI is simple and effective, but it woul have been nice to make it more
   visually appealing to "WoW" th user.

## 4. Whether the final app met the original goal

   Yes the app meets the goal of recording expenses and will be useful to the intended user.
   We succeeded in implementing all of the core features.
